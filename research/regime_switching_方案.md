# Regime Switching（市场状态切换）方案设计

> 目标：把"现在这套超参 + 因子组合"从**全局最优解**降级为**某一类市场环境下的最优解**，
> 并建立"识别环境 → 选用对应策略"的闭环。
> 本文只做方案与可行性分析，不改代码。

---

## 零、现状盘点：你的地基比想象中好

| 已有资产 | 对 regime switching 的价值 |
|---|---|
| `backtest/timing.py` 7 个择时类（`MATiming` / `StyleConvergenceTiming` / `BlindWindowTiming` / `LGBMDriftTiming` / `HybridTiming` …） | 已有"日度仓位择时"的抽象与实现，regime 可以复用同样的注入方式 |
| `BaseTimingStrategy.prepare(start, end)` + `get_position_ratio(date)` | 预计算 + 按日查询的接口范式，可直接照搬到 regime 检测器 |
| 引擎结构：清仓 → 次日建仓（`if not positions:`）、`next_signal_idx` 周期节点 | **天然适合切换策略**：每次建仓之间必然有一段空仓窗口，切换点没有持仓摩擦 |
| `self.timing.on_batch_sold(profit)` 回调 | 已支持把"批次已实现收益"反馈给择时层，可升级为反馈给 regime 层（在线学习） |
| 截面数据 724 列 × 2123 天（含 vol/amount/turnover/pe/pb/total_mv/融资融券/龙虎榜/资金流） | 构造市场状态指标所需的原料**基本齐全**，不需要新数据源 |
| `LGBMConfig` 已是独立配置对象（window / label_period / weight_halflife / top_weight_factor / factor_cols / lgbm_params） | 做"同一模型不同配置"几乎是零成本 |
| `strategy/selection/` 下已有 6 个策略族（LGBM / LGBMRanker / LGBMBinary / LGBMDynamic / ElasticNet / ICWeighted / TabNet） | 做"不同环境换模型族"的可选项已经存在 |

**一句话结论：不需要推倒重来。** 主要工作量在"环境刻画"和"引擎路由"两处，策略本体改动很小。

## 一、总体架构（四层）

```
                    ┌─────────────────────────────────────┐
  L0 数据层          │  data/market  截面（2123天 × 724列）  │
                    │  data/market_state.parquet  【新建】  │  ← 月度市场状态特征
                    └──────────────┬──────────────────────┘
                                   │
  L1 环境层          ┌─────────────▼──────────────────────┐
   RegimeDetector    │  月度打标 + 防抖（迟滞/最短驻留期）   │
                    │  输出：regime_id 或 regime_prob 向量  │
                    └─────────────┬──────────────────────┘
                                   │  只在空仓窗口生效
  L2 路由层          ┌─────────────▼──────────────────────┐
   StrategyRouter    │  regime → (选股策略, 因子集, 超参,     │
                    │            top_n, 持有期, 仓位, 风控)  │
                    └─────────────┬──────────────────────┘
                                   │
  L3 执行层          ┌─────────────▼──────────────────────┐
   BacktestEngine    │  现有引擎（改动点：strategy 变可路由） │
                    └─────────────────────────────────────┘
```

**关键设计约束（先定死，避免后期返工）：**

1. **所有 regime 判断必须 point-in-time**：月末数据只能在次月首交易日之后使用。
   建议显式加 `release_lag=1`（月），回测里直接验证"如果滞后 2 个月会怎样"。
2. **切换只在空仓窗口发生**：当前引擎建仓前必然清仓，所以切换点是免费的。
   但要注意"持仓中途 regime 变了"的处理——建议**持仓期间锁定 regime**（一批从头到尾用同一策略）。
3. **regime 标签要能被"回看"**：每批交易都要落 `regime_id` 到 `batch_alias_profit.csv`，
   否则后面做归因分析时无法切片。

## 二、能力 1：策略画像与适配环境分析

### 2.1 要产出什么

对**当前这套策略**（以及未来每一套）输出一张"能力画像卡"：

| 维度 | 具体指标 |
|---|---|
| 收益特征 | 总/年化收益、Bootstrap 置信区间、右尾频率（>+10% 占比）、基础盘（剔除大涨批次后） |
| 风险特征 | 最大回撤、回撤持续天数、波动率、下行波动、Calmar |
| 选股能力 | 相对全池超额（t 值）、相对无脑动量基准（t 值）、Top5 内部 IC、滚动 ICIR |
| 风格暴露 | 市值/估值(pe,pb)/动量/波动/流动性/行业 六个维度的暴露度 + 中性化后残差收益 |
| **环境适配** | **按 regime 切片**的上述全部指标（这是新增的核心产出） |
| 时段表现 | 按年、按牛熊段（可用指数 MA 划分）、按波动率分位切片 |

### 2.2 "中性化后残差收益"怎么做（关键）

这是判断"到底是 alpha 还是风格 beta"的标准做法，你的数据完全够：

```
对每个调仓日 T：
  1. 取全截面，对 5 日收益做截面回归：ret ~ β1·ln_mv + β2·ln_pb + β3·ret_20d
     + β4·volatility_20d + β5·ln_turnover + Σ行业哑变量
  2. 残差 = 该股票的"纯 alpha 收益"
  3. 策略 Top5 的残差均值 = 剥离风格后的真实选股能力
```

**判读**：如果原始超额 +1.53% 但残差 ≈ 0 → 全是风格 beta，换环境就失效；
如果残差仍显著为正 → 真 alpha，可跨环境迁移。

### 2.3 选项与权衡

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **A. 离线归因脚本**（推荐先做） | 扩展现有 `analyse/backtest_report.py` | 零引擎改动，立刻可用 | 只做描述，不做决策 |
| B. 常驻归因模块 | 回测时实时计算并落盘 | 一次跑完，省二次计算 | 拖慢回测 |
| C. 独立研究 notebook | 灵活探索 | 便于迭代想法 | 与生产代码脱节，易腐化 |

**建议 A**：把归因做进 `analyse/backtest_report.py`，并在 `batch_alias_profit.csv` 里加 `regime_id` 列。

## 三、能力 2：分环境设计选股策略

### 3.1 三个可调节层次（由易到难）

| 层次 | 可调项 | 成本 | 过拟合风险 |
|---|---|---|---|
| **L1 超参** | `window`(训练窗口) / `label_period` / `weight_halflife` / `top_weight_factor` / `top_n` / `holding_period` | 低 | **中**（组合爆炸） |
| **L2 因子集** | 从 198 个因子里选子集：动量类 / 反转类 / 质量类 / 量价类 / 资金流类 | 中 | 高 |
| **L3 模型族** | LGBM vs LGBMRanker vs ICWeighted vs ElasticNet | 高（训练成本翻倍） | 最高 |

**强烈建议先只做 L1，最多 L1+L2。** 理由见 3.3。

### 3.2 环境 → 策略 的直觉映射（待验证，不是结论）

| 环境特征 | 假设有效的配置方向 | 待验证 |
|---|---|---|
| 趋势上行、低波动 | 更长训练窗口、动量因子加权、持有期拉长 | ☐ |
| 震荡、高离散度 | 短训练窗口、反转+量价因子、持有期缩短 | ☐ |
| 高波动、恐慌 | 质量/低波因子、降低仓位或空仓、缩短持有期 | ☐ |
| 极端投机（涨停家数多） | 资金流/龙虎榜因子加权 | ☐ |

> ⚠️ 这些是**假设**，不是结论。必须由 2.1/2.2 的归因结果来定，不能拍脑袋分配。

### 3.3 ⚠️ 统计功效警告（这是本方案最大的风险）

当前样本：131 批。若切 4 个 regime，每个约 33 批。

- 33 批做参数选择 → **几乎必然过拟合**
- 经验门槛：**每个 regime 至少 50~80 批**才勉强能做参数选择

**所以必须先做一件事**：把回测区间从 665 天扩到 2123 天（2018-2026），
得到约 **420 批**，切 4 个 regime 后每个 ~105 批，才具备基本统计功效。
（这也正好是你已经在准备的 2018 年以来回测，两者要合并做。）

**补充缓解手段**：
- regime 数量先从 **2~3 个**起步，不要一上来 6 个
- 用** ranking 而非优化**选参数：不看"哪组参数收益最高"，看"哪组在多个子时段都排前列"
- 强制**参数平滑**：相邻 regime 的超参不要剧烈跳变（如 window 只允许 250/375/500 三档）

## 四、能力 3：市场环境风向标（月度）

这是整个方案的**成败关键**，也是最需要谨慎的一环。

### 4.1 候选指标（按信息维度分组，可自由组合）

| 组 | 具体指标 | 数据可得性 | 说明 |
|---|---|---|---|
| 趋势 | 指数 MA20/MA60/MA120 多空排列、MA60 斜率（月） | ✅ `000510.SH` / `932000.CSI` | 最经典，但滞后明显 |
| 波动 | 指数 20/60 日已实现波动率的**历史分位** | ✅ 可算 | 用分位数而非绝对值，跨时代可比 |
| 流动性 | 全市场日成交额同比 / 换手率分位 / 融资余额增速 | ✅ amount、turnover、rzye | 量在价先 |
| **离散度** | 个股收益横截面标准差（dispersion） | ✅ 可算 | **选股型策略的土壤**：离散度高 = 选股有用 |
| **因子有效性** | 全因子滚动 RankIC 均值 / IC>0 占比 | ✅ 可算 | **直接衡量"选股能不能赚钱"** |
| 风格轮动 | 价值vs成长、大vs小、动量vs反转 的滚动相对强弱 | ✅ 可算（pe/pb/mv/ret_20d 分组收益） | 决定用哪类因子 |
| 投机氛围 | 涨停/跌停家数占比、ST 占比、连板高度 | ✅ pct_chg、is_st | A 股特色，很有效 |
| 资金 | 北向/主力资金流、龙虎榜活跃度 | ✅ moneyflow、top_list | 已有数据 |
| 宏观代理 | 利率、信用利差 | ❌ 缺 | 可用"金融板块相对走势"做粗糙代理 |

**我最看好的三个**（信息量高、噪音低、可得）：
1. **截面离散度** — 直接决定选股策略有没有空间
2. **滚动因子 RankIC** — 直接衡量选股信号的当期有效性
3. **风格相对强弱**（大/小 + 价值/成长）— 直接决定用哪类因子

### 4.2 Regime 定义方式：四个选项

| 方案 | 做法 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|---|
| **A. 人工规则** | 如"MA60 上 + 波动<中位 + 离散度高" → R1 | 可解释、可控、易调试 | 主观、易事后拟合 | ⭐⭐⭐ |
| **B. 无监督聚类** | 对月度特征做 KMeans / GMM，得到 k 个状态 | 客观、能发现未知状态 | 难命名、k 难选、簇不稳 | ⭐⭐⭐⭐ |
| **C. 监督式** | 用"策略未来收益"作标签反推环境 | 直接对目标优化 | **严重过拟合**，且循环论证 | ⭐（不建议单独用） |
| **D. 混合（推荐）** | 先聚类 → 人工检查每个簇的特征均值 → 命名 → 用规则复现 | 兼顾客观与可解释 | 工作量最大 | ⭐⭐⭐⭐⭐ |

### 4.3 防抖机制（必须做，否则切换频繁到无法交易）

用户要求"以月为单位、不轻易改变"，对应四种机制，建议**全部叠加**：

1. **月度采样**：每月最后交易日计算一次，月中不变
2. **连续确认**：需连续 N 个月（建议 N=2）落入同一状态才切换
3. **迟滞（hysteresis）**：切换到 R2 的阈值 > 切回 R1 的阈值（留缓冲区）
4. **最短驻留期**：进入某状态后至少驻留 3 个月才允许切换

再加一个**成本预算**：限制每年最多切换 2~3 次（超出则强制保持），
这能直接把"切换次数"变成一个可调的过拟合防护旋钮。

### 4.4 双层结构建议（重要补充）

月度风向标有 1~2 个月滞后，A 股拐点很急。**建议做成双层**：

- **主层（月度，慢）**：决定用哪套选股策略 → 你要求的"风向标"
- **快层（日度，快）**：只管**仓位**，不管选股。极端波动/流动性枯竭时快速降仓

这样"策略切换慢、风险响应快"，避免月度信号在拐点上裸奔。
快层可以直接复用现有 `BlindWindowVolTiming`（已经有波动率择时实现）。

### 4.5 落地产物

新增 `data/market_state.parquet`（月度 × 指标），字段建议：

```
month, ret_1m, vol_60d_pct, dispersion, ic_mean_60d, icir_60d,
turnover_pct, amount_yoy, limitup_ratio, st_ratio,
size_spread(小-大), value_spread(价值-成长), mom_spread(动量-反转),
regime_id, regime_name, switch_flag
```

打标后**必须人工检查**：把每个 regime 对应的历史时段列出来，
看是否与你的市场直觉吻合（如 R_熊市 应该覆盖 2018、2022）。**这一步不能省。**

## 五、能力 4：引擎改造支持自动切换

### 5.1 三种改造方案

| 方案 | 改动 | 引擎变化 | 适用 |
|---|---|---|---|
| **A. Router 包装（推荐先做）** | 新建 `StrategyRouter(BaseStrategy)`，内部持有 N 个子策略 + regime 检测器，按 `date` 委托 | **引擎零改动**（`self.strategy` 换成 router 即可） | 快速验证、风险最低 |
| B. 引擎内注册表 | `engine.strategy_registry: dict[regime, strategy]`，在步骤⑤按当日 regime 取 | 引擎加 ~15 行 | 需要 regime 同时驱动 top_n / 持有期时 |
| C. 完整 regime 上下文 | 引入 `RegimeContext` 对象，统一驱动 策略+仓位+持有期+风控+卖出规则 | 引擎改动较大 | 后期完整方案 |

**建议路径：先 A 跑通验证，再升级到 B。** A 的最大好处是"能立刻用现有引擎做 A/B 对比"。

### 5.2 三个必须解决的工程问题

**问题 1：模型训练成本爆炸**
当前 LGBM 每日重训 ≈ 9.6 秒/交易日。
若 4 个 regime 策略每天都训练：2123 天 × 4 × 9.6s ≈ **22.6 小时**。

| 对策 | 说明 |
|---|---|
| **懒加载 + 预热** | 只在某 regime 进入"候选"（连续 1 个月命中）时才开始训练它；其余时间不训练 |
| **仅激活态训练** | 只有当前 regime 对应的策略每日训练，其他冻结 |
| **共享主干 + 差异化头部** | 所有 regime 共享一个每日训练的模型，只对 top_n/因子权重/持有期做差异化 → **成本几乎不增加**，但表达力弱一些 |

**推荐：先做"激活态训练 + 预热 K 天"**（切换前 20 个交易日预热目标策略），能把成本压到接近单策略。

**问题 2：切换时的持仓处理**
- 建议：**持仓期间锁定 regime**（一批从头到尾同一策略）。实现最简单，也避免"半仓 A 策略半仓 B 策略"的归因混乱。
- 备选：混合持仓（新旧策略各半）→ 平滑但记账复杂，不利于归因。**不推荐一开始做。**

**问题 3：软切换 vs 硬切换**

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **硬切换** | winner-take-all，只用当前 regime 的策略 | 归因清晰、可解释 | 切换点断崖，若判错则整段错 |
| **软加权** | 按 regime 概率对多套策略的 **score 做加权融合** | 平滑、容错、不会整段判错 | 归因模糊、需要校准权重 |
| **混合** | 主策略硬切换 + 30% 仓位做多策略融合 | 折中 | 复杂 |

**推荐：先硬切换（好验证），跑通后再试软加权做对比。** 软加权在 regime 判别不准时通常更稳。

### 5.3 回测口径（容易埋雷的地方）

1. regime 标签的**发布延迟**必须显式建模（`release_lag`），并在报告中披露"滞后 1 月 / 2 月"两套结果
2. regime 检测器本身**不能看到未来**——所有指标的滚动窗口只能用 T 月及之前的数据
3. 报告里必须给出**"完美预知 regime"的上界**和**"固定用单一策略"的下界**，
   实际切换策略的收益应落在其间。若超过上界 → 一定有 bug；若低于下界 → 切换是负价值

## 六、可行性总评

| 维度 | 评估 | 说明 |
|---|---|---|
| 数据可行性 | ✅ **充分** | 离散度、RankIC、风格价差、投机氛围都能从现有截面算出；仅宏观数据缺失（可用代理） |
| 算力可行性 | ⚠️ **需优化** | 单策略 2123 天 ≈ 5.6h；4 策略全训 ≈ 22h。用激活态训练可压回 ~7h |
| 统计可行性 | ⚠️ **当前不足，扩容后可** | 131 批 → 切 4 档只有 33 批/档。必须先跑 2018-2026（~420 批） |
| 工程可行性 | ✅ **良好** | Router 方案引擎零改动；timing 抽象可直接复用 |
| 过拟合风险 | 🔴 **高** | 本方案最大的敌人。对策：regime 先用聚类、限制数量、参数只分档不寻优、切换次数预算、样本外验证 |
| 落地价值 | ✅ **高** | 若 regime 判别有效，收益改善可能远大于继续调单套超参 |

## 七、分阶段路线（建议）

| 阶段 | 产出 | 依赖 | 工作量 |
|---|---|---|---|
| **P0** | `data/market_state.parquet` 月度特征表 + regime 打标（k=3，混合法）+ 历史时段人工核对 | 无 | 中 |
| **P1** | 策略画像卡：按 regime 切片的收益/风险/IC/风格暴露 + 中性化残差 | P0 + 2018-2026 回测结果 | 中 |
| **P2** | **离线**对比：每个 regime 分别用当前策略回测，找出"哪个环境赚钱、哪个环境亏钱" | P1 | 低（纯分析） |
| **P3** | 为每个 regime 设计 2~3 组候选配置（只动 L1 超参 + L2 因子子集），**在各 regime 内部**做 ranking 选择 | P2 | 中 |
| **P4** | 引擎改造：`StrategyRouter`（方案 A，硬切换）+ 激活态训练 + 持仓期锁定 regime | P3 | 中 |
| **P5** | 防抖三件套（连续确认/迟滞/最短驻留）+ 切换次数预算 + 快层日度仓位 | P4 | 低 |
| **P6** | 样本外验证：2018-2022 定 regime 与配置，2023-2026 验证；对比"单策略"下界与"完美预知"上界 | P5 | 中 |

**P0~P2 可以先并行做完**，它们不需要改任何生产代码，且直接回答"我现在这套策略到底适配什么环境"。

## 八、需要你拍板的决策点

1. **regime 定义方式**：人工规则 / 无监督聚类 / 混合（我推荐混合）
2. **regime 数量**：2 / 3 / 4（我推荐先从 3 起步）
3. **差异化层次**：只动超参 / 超参+因子集 / 连模型族一起换（我推荐前两层）
4. **切换方式**：硬切换 / 软加权（我推荐先硬后软做对比）
5. **是否引入快层日度仓位**：要（更稳）/ 不要（更简单）
6. **2018-2026 全区间回测谁来跑**：你跑完给我结果 / 我挂后台跑（约 5.6 小时）
